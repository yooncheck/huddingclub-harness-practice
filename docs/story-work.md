# 허들링 앱 작업 스토리 (손으로 했던 방식)

[story-service.md](story-service.md)는 "무엇을 위한 일인지"의 기준이고, 이 파일은 "내가 실제로 어떻게 했는지"의 기록이다. 둘을 섞지 않는다.

상태: 문장은 사용자 원문. 게이트·6번 분할은 🔸(Claude가 추론, 사용자가 "알아서"로 위임). 틀리면 고친다.

## 표기법

- `⏸` = 멈칫한 지점 (게이트). 사용자가 직접 표시한 곳은 없다. 🔸는 Claude 추론.
- `→` = 다른 사람/도구로 넘어가는 지점 (에이전트 경계).

## 문장

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다. →
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석 내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다. →
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다. → ⏸🔸
6. 컨펌된 시안을 기반으로
   - 6-a. 🔸 디자인 토큰을 제작한다. →
   - 6-b. 🔸 컴포넌트를 제작한다. →
   - 6-c. 🔸 화면 디자인에 들어간다. →
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다. → ⏸🔸
