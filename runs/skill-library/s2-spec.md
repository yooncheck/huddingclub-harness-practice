# S2 화면 설계 문서 — 스킬 라이브러리

근거: docs/prd.md §6-3, §7, §9. 🔸 = PRD에 없어서 임시로 정한 값 (맨 아래 "확인이 필요한 것" 참고).

## 화면 목적

하이서가 만든 검증된 스킬/프롬프트를 구조화된 카드로 찾아서 쓰게 한다. 보고 끝나는 것이 아니라 복사하거나 내려받아 업무에 바로 쓰고, 관련 미션으로 이어지게 한다.

## 화면 구성 (모바일 390×844, 단일 컬럼)

1. **목록 화면**: 상단 제목, 검색창, 카테고리·태그 필터 칩 행, "총 N개", 스킬 카드 목록
2. **스킬 카드 상세**: 카드 필드 전체, 프롬프트 박스와 복사 버튼, 파일 다운로드, 사용 순서, 예시 결과, 관련 미션 링크
3. **필터 시트**: 칩이 한 줄에 안 들어갈 때 올라오는 바텀시트. 하단에 "초기화"와 "적용하기"

### 카드 필드 (PRD §6-3)

스킬명, 카테고리, 난이도, 추천 대상, 사용 도구, 언제 쓰나요?, 준비물, 프롬프트 또는 파일, 사용 순서, 예시 결과, 주의할 점, 업데이트 날짜, 권한(무료 / 유료 / 특정 코호트 전용)

### 기능 (PRD §6-3 필수 기능 8개)

카드 목록, 검색, 태그 필터, 복사 버튼, 파일 다운로드, 예시 결과 보기, 난이도 표시, 관련 미션 연결

### 상태

- 목록이 비었을 때: 한 줄 안내 + "필터 초기화" 링크
- 복사 성공: "복사했어요" 문구로 알림 (색이 아니라 글자로 구분)
- 잠긴 카드(권한 없음): 스킬명, 카테고리, 난이도, 추천 대상, 언제 쓰나요?만 보이고 프롬프트·파일·예시는 가려진다. 로그인 또는 유료 전환 CTA를 둔다.

## 역할별 접근

| 역할 | 무료 카드 | 유료 카드 | 코호트 전용 카드 |
|---|---|---|---|
| guest | 목록과 요약만. 상세·복사·다운로드는 로그인 CTA | 요약만 (미리보기) | 요약만 (미리보기) |
| free | 전체 사용 | 요약만 (미리보기) + 유료 전환 CTA | 요약만 (미리보기) |
| paid, seller, admin | 전체 사용 | 전체 사용 | 해당 코호트만 전체 사용 🔸 |

## 허용 상태값

이 화면에는 제출물이나 자산 상태 UI가 없다. 제품 전체 허용값은 harness/default-content.md와 같다.

- 제출물: draft, submitted
- 공개 범위: private, member_only, sale_requested
- 검수 상태: draft, pending, revision_requested, approved, rejected

## 이 화면의 정책 값 기록 (해당 UI 없음)

이 화면에는 판매 신청, 검수, 승인 버튼이 없다. 아래 JSON의 C1~C5용 값은 화면 동작이 아니라 **제품 전체 정책(PRD §6-5, §6-7, §7-4, §14)을 옮겨 적은 것**이다. 자산 등록 화면과 운영자 검수 화면을 만들 때 같은 값을 쓴다.

## 범위 밖 항목

이번 MVP 1차에서 만들지 않는다 (PRD §9): 허들링 픽 노출, 구매·결제·정산, 수익 내역, 미션 피드백, AI 1차 검수, 리뷰와 평점, 자동 추천, 앱 내 커뮤니티 피드, 실시간 채팅.

## 확인이 필요한 것 (PRD에 없어서 묻는다)

1. 난이도 단계: PRD에는 "난이도 표시"만 있다. 🔸 입문 / 중급 / 고급 3단계로 임시 정했다.
2. 카테고리: PRD §6-3에는 값이 없다. 🔸 §6-1의 6개(AI 실무, Figma + AI, 바이브코딩, 자동화, 콘텐츠 제작, 1인 사업가 운영)를 재사용한다.
3. "특정 코호트 전용": 사용자가 어느 코호트인지 판단하는 데이터가 PRD 데이터 모델(User)에 없다. 🔸 일단 "해당 코호트만 사용"으로 적었다.
4. 관련 미션 연결의 목적지: 미션 상세 화면은 이번 하네스 범위 밖이라 링크만 둔다.
